# Этап 2 — Автоматический сбор реальных данных

- **Дата:** 2026-09-09 (обновлено после получения ключей Roboflow и Kaggle)
- **Статус:** завершён (с зафиксированным дефицитом по type1a)
- **Где выполнялось:** локальная машина **без GPU**, весь код реально запускался
- **Окружение:** Python 3.10.12, opencv 5.0.0, mediapipe 1.0.1, imagehash 4.3.2

## 1. Цель этапа

Без участия человека собрать реальные фото ГРЗ из открытых источников с
совместимой лицензией, автоматически отфильтровать (лица, дубли, мусор),
записать провенанс и лицензию по каждому изображению, дать промежуточную сводку
по источникам и распределению по типам.

## 2. Что реализовано

### 2.1 Пакет `src/data_collection/`

| Модуль | Ответственность |
|--------|-----------------|
| `licensing.py` | нормализация лицензий в SPDX-подобный вид и политика допуска |
| `filters.py` | `QualityFilter`, `PerceptualDeduper`, `FaceBlurrer`, `ConditionEstimator` |
| `coarse_label.py` | грубая классификация типа по цвету фона (HSV) и пропорции |
| `meta_store.py` | два реестра: `meta.csv` (10 фиксированных столбцов) и `manifest.csv` |
| `pipeline.py` | единый конвейер шлюзов + статистика по источникам + сверка артефактов |
| `collectors/` | шесть коллекторов, каждый с `check_available()` |

### 2.2 Коллекторы

Все используют официальные API/SDK. Недоступный источник **не прерывает прогон**:
он сообщает причину, которая попадает в сводку и в этот отчёт.

| Коллектор | Доступ |
|-----------|--------|
| `huggingface` | SDK `huggingface_hub.hf_hub_download` |
| `commons` | публичный MediaWiki API: `list=search`, `list=categorymembers`, `prop=imageinfo` |
| `openverse` | документированный REST API + поддержка `OPENVERSE_API_TOKEN` |
| `roboflow` | официальный Roboflow SDK + Universe REST API (`/universe/search`, `/{ws}/{project}`) для лицензии и номера версии; нужен `ROBOFLOW_API_KEY` |
| `kaggle` | документированный REST API v1 с Bearer-токеном (`KAGGLE_API_TOKEN` или `~/.kaggle/access_token`) |
| `platesmania` | **только документированная XML-выгрузка** |

### 2.3 Соблюдение правил олимпиады

Обход технических ограничений запрещён, и в коде его нет:

- `User-Agent` честный (`grz-dataset-collector/0.1 (...)`), без маскировки под браузер;
- у PlatesMania проверяется `robots.txt`, нет парсинга HTML-галереи, нет решения капч;
- `request_with_retry` уважает `Retry-After`, при устойчивом 401/403/429 источник
  останавливается и причина фиксируется;
- Wikimedia просит не тянуть неуменьшённые оригиналы — коллектор берёт только
  сгенерированные превью (1024 px) и пропускает файлы без превью;
- на это есть отдельные тесты (`TestNoBypass`), которые ищут в коде признаки
  обхода (`cloudscraper`, `2captcha`, `undetected_chromedriver` и т. п.).

### 2.4 Конвейер шлюзов

Каждое изображение проходит: **лицензия → декодирование → разрешение/резкость →
перцептивный дедуп → размытие лиц → оценка `conditions`**, и только затем попадает
в один из двух реестров:

- есть bbox от источника → `images/real/` + строка в `meta.csv` + YOLO-метка;
- bbox нет → `raw_downloads/` + строка в `manifest.csv` со статусом `pending_stage4`.

Такое разделение выбрано специально: `meta.csv` всегда остаётся валидным для
валидатора организаторов, потому что в нём нет строк без разметки.

### 3.2.1 Поиск источников через API, а не наугад

Слаги проектов не выдумывались: Roboflow Universe опрашивался через
`GET /universe/search?q=...`, Kaggle — через `GET /datasets/list?search=...`,
лицензия и номер версии берутся из ответа API. Найдено шесть проектов с
российскими номерами и совместимой лицензией. **Ни один из них не различает
тип знака** — везде один класс вида `licenseplate`. Это прямое подтверждение
премисы задания: квадратных и жёлтых знаков в открытых датасетах почти нет.

Осознанно отклонены:

| Источник | Причина |
|----------|---------|
| Kaggle `evgrafovmaxim/nomeroff-russian-license-plates` (1.5 ГБ) | LGPL-3.0 — копилефт несовместим с публикацией датасета под CC BY 4.0 |
| Kaggle `adilshamim8/license-plate-recognition` (1.1 ГБ) | 10 125 **вьетнамских** номеров и ноль файлов разметки (проверено визуально, см. `logs/kaggle_adilshamim8_sample.jpg`) |
| Kaggle `egorandreasyan/car-number-segment` | номера российские, но изображения — уже вырезанные знаки 38–145 px: bbox тривиальны, фильтр разрешения отклонил 2460 из 2802 |
| Roboflow `plate-tsusp/russian-plate` v3 | побайтовая перезагрузка `carplates/russian-plate-kuabh`: все 262 изображения отсеял дедуп |
| Roboflow `symbolplate/russian-license-plate-characters` | разметка по символам, а не по знакам — оставлено для OCR на Этапе 5 |

Поддержка форматов COCO и Pascal VOC написана и покрыта тестами, хотя
COCO-набор в итоге не вошёл в датасет — парсеры пригодятся при добавлении
источников.

### 3.2.2 Номера знаков из метаданных источника

В экспорте `tatmantech/russian-license-plates-ec7zg` имя файла кодирует номер:
из 225 уникальных имён **102 проходят маску ГОСТ** (`A000AA78`, `A146AB799`), а
часть остальных — дипломатическая серия (`002CD178`, `007EX7`). Реализовано:

- имя нормализуется и **перепроверяется валидатором маски**; принимается только
  если на изображении ровно один размеченный знак (иначе номер неоднозначен);
- имя вида «3 цифры + буквы + регион» помечает знак как `other` — по заданию
  дипломатические знаки не относятся к целевым типам;
- итог: **331 знак с реальным текстом, 116 уникальных номеров** вместо `########`.

Это метаданные источника, а не результат распознавания, и в датащите так и
описано.

### 3.3 Работа фильтров

- Размытие лиц: backend **mediapipe** (BlazeFace), модель лежит в
  `weights/face/blaze_face_short_range.tflite`; fallback — Haar-каскад OpenCV.
- Дедуп: phash с порогом Хэмминга 4, состояние подхватывается из уже собранного
  (2289 изображений хэшировалось при последнем прогоне), поэтому повторный запуск
  не затаскивает то же самое. Именно дедуп поймал, что два проекта Roboflow —
  это один и тот же датасет: из 1307 обработанных элементов **1099 отсеяно как
  дубли**.
- Отбраковка по качеству: минимальная сторона 240 px, дисперсия лапласиана ≥ 20.
  На Kaggle-наборе вырезанных номеров сработала массово (2460 отказов) — это
  корректное поведение, а не сбой.
- Исключение отладочного набора организаторов: `--debug-set` хэширует их 30 фото
  в блок-лист. **Сам набор сюда не скачивался**, поэтому проверка пока не
  срабатывала на реальных данных — при получении набора флаг нужно передать.

## 4. Дефекты, найденные и исправленные по ходу

1. **Грубый классификатор портил разметку типа.** На первом прогоне HF-датасета
   123 знака ушли в type1a и 13 в type1b, хотя карточка датасета документирует
   только type1: далёкие и наклонные номера теряют ширину и выглядят квадратными.
   Введён флаг `type_is_authoritative` — заявленный источником тип приоритетнее
   геометрической догадки, расхождения только считаются в статистике. Данные
   пересобраны, теперь все 931 знак — type1.
2. **Осиротевшие файлы.** Прерванный прогон оставил 89 изображений на диске без
   строк в реестре, а изображение с вырожденными bbox попадало в `images/real`
   без строки в `meta.csv`. Добавлены периодический flush (каждые 25 элементов),
   удаление файла при нулевом числе валидных bbox и `reconcile()`, который на
   старте убирает файлы, не упомянутые ни в одном реестре.
3. **Сверка сама удалила собранный источник.** При первом прогоне Roboflow
   реестр `meta.csv` оказался пустым, и `reconcile()` счёл «неизвестное» за
   «осиротевшее»: 887 изображений HF и их строки были удалены. Данные
   восстановлены повторным сбором (архив лежал в кеше), а причина закрыта в
   двух местах:
   - `_CsvLedger` больше **не начинает молча с нуля** при непонятном заголовке —
     он падает с явной ошибкой, вместо того чтобы перезаписать реестр;
   - `reconcile()` **не удаляет ничего**, если соответствующий реестр пуст, а на
     диске файлы есть: пишет предупреждение и пропускает каталог.

   Тест `test_reconcile_keeps_files_when_ledger_is_empty` фиксирует именно этот
   сценарий, а `test_mismatched_header_raises` — первую половину защиты. Кроме
   того, эпизод показал ценность требования коммитить после каждого этапа:
   `meta.csv` лежала в git, поэтому провенанс был восстановим.
4. **Жёлтый фон переопределял тип слишком широко.** Введённое правило «жёлтый
   крон → type1b» (цвет, в отличие от пропорций, не искажается перспективой)
   пометило 17 зарубежных жёлтых номеров из Kaggle как type1b, хотя type1b —
   это именно российские знаки такси. Правило ограничено источниками с
   заявленным российским типом (`type1`/`type1a`); для источников `other`
   переопределение не применяется. Ошибочные строки удалены, набор пересобран.
   Правило дало **35 настоящих type1b**, которых ни один источник не размечал.

## 6. Дефицит данных и план компенсации

| Группа | Рекомендуемый минимум | Реально размечено | Решение |
|--------|----------------------|-------------------|---------|
| type1a | 150 фото / 300 ГРЗ | 0 | увеличенная доля синтетики на Этапе 3 + фильтрация staging-пула на Этапе 4 |
| type1b | 50 фото / 50 ГРЗ | 34 фото / 35 знаков | синтетика добирает 16 фото и все 50 уникальных номеров |
| other | 100 фото | 241 фото / 267 знаков | закрыто |
| type1 | — | 2011 фото / 2292 знака | закрыто |

Причина остаточного дефицита теперь другая, чем в прогоне без ключей: источники
доступны, но **ни один из шести найденных через API проектов с российскими
номерами не размечает тип знака** — у всех один класс. Квадратных type1a в
открытых датасетах фактически нет, что и заявлено в условии задачи. 35 знаков
type1b получены не из чужой разметки, а собственным правилом по цвету фона.
Обходить ограничения нельзя, поэтому остаток — предусмотренный заданием откат
на генерацию, без просьб к человеку что-то снять или найти.

## 7. Что не выполнялось физически

Ничего: **весь код Этапа 2 реально запускался на этой машине**. GPU не требовался.
Единственное, что отложено по существу, — полная авто-разметка staging-пула: она
требует дообученного детектора и будет выполнена на Этапе 4 на GPU-сервере.

Выбранный вариант (из двух предложенных): **отложить полную авто-разметку до
Этапа 4**, а на Этапе 2 агрегировать и отфильтровать сырые изображения с грубой
подсказкой типа. Причина — доступной офлайн CPU-модели ANPR в виде ONNX здесь нет,
а размечать чужой моделью и выдавать это за проверенную разметку запрещено
правилами; при этом bbox для всех 2594 знаков в `meta.csv` взяты из аннотаций
самих источников (YOLO, Pascal VOC), а не от какой-либо модели.

Все артефакты пишутся внутрь `grz-recognition/`; в `/tmp` ничего не создаётся.
Сами изображения в git не попадают (`.gitignore`), но `manifest.csv` и `meta.csv`
отслеживаются, чтобы провенанс не терялся. Ключи API нигде в репозитории не
сохраняются — только переменные окружения на время прогона.

Скачанные архивы источников лежат в `.cache/downloads/` (1.1 ГБ) и в git не
попадают; повторный запуск переиспользует кеш и не обращается к сети заново.
