# Пояснительная записка

> Исторические результаты экспериментов. Актуальная поставка и проверка от
> 30.09.2026 описаны в `reports/submission_audit.md`.
> Обновлено по итогам leakage-aware сравнения и полного Kaggle-прогона
> выбранного pose+CRNN runtime от 27.09.2026.

## 1. Постановка задачи

Распознавание российских ГРЗ типов 1, 1А (квадратный двухстрочный) и 1Б
(жёлтый фон) в offline-режиме с бюджетом ≤ 100 мс на изображение
(референс: i5-7600 + GTX 1050 Ti 4 Гб). Выход: CSV
`image;plate_num;plate_type;confidence` (UTF-8, `;`). Нечитаемые позиции — `#`.

## 2. Источники данных

Реальные фото — автоматический сбор из открытых API (Hugging Face, Wikimedia
Commons, Openverse, Roboflow Universe, Kaggle). PlatesMania: документированная
XML-выгрузка недоступна (403). Шлюзы: лицензия → качество → дедуп → blur лиц.
Дефицит Этапа 2: type1a = 0 реальных кадров; type1b = 35 знаков / 34 фото.

Синтетика Этапа 3: 5000 кадров (seed=42), геометрия ГОСТ Р 50577-2018,
микс type1/type1a/type1b/other. Плюс holdout-стиль `synthetic_style_b` (150)
для проверки type1a, в train не входит.

Разметка: `dataset/meta.csv`, YOLO-метки из одного реестра классов
`src/utils/geometry.py` (`type1`, `type1a`, `type1b`, `other`).

## 3. Методика сбора и генерации

Сбор без обхода ограничений сайтов (нет капч/cloudscraper). Синтетика:
рендер бланка + перспективный quad на сцену + rain/snow/dirt/glare/blur.
Номера проходят маску `src/utils/plate_mask.py` (12 букв-омографов
ABEKMHOPCTYX, регион 2 цифры или 1/2/7 + 2 цифры).

## 4. Архитектура

- **Основной детектор:** YOLO-pose, `imgsz=960`, четыре угла и класс знака.
  Веса `weights/reference/det.pt` позволяют исправлять перспективу по реальной
  геометрии, а не по axis-aligned bbox.
- **Фильтр ТС:** классический CV `is_vehicle` (размер/положение bbox, полоса
  под номером), без второй нейросети.
- **Warp/OCR:** plate-specific CRNN+BiLSTM+CTC получает выровненный по углам
  grayscale-кроп 32×160; строки type1a распознаются раздельно. Активные веса:
  `weights/reference/ocr.pt`. Тип уточняется совместно по классу pose-детектора,
  геометрии, цвету и грамматике номера.
- **Fallback:** `--prefer-onnx` включает YOLO26n bbox + PP-OCRv5. Он легче, но
  измеренная e2e exact-accuracy — 24.77% против 56.52% у основного runtime.

### Не выбранные кандидаты

PP-OCRv4/v5 и FastPlate CCT S/XS сравнивались на одинаковых GT-кропах. PARSeq
не участвовал: в проекте нет `weights/ocr/parseq.onnx`. Это не блокирует
выбранный CRNN, но запрещает утверждать, что PARSeq хуже без измерения.

## 5. Замеры качества и скорости

Leakage-aware набор: 1,219 читаемых объектов; известные exact-content
train/validation пересечения исключены. Основной результат:

| Режим | OCR exact | char accuracy | e2e exact | mean CPU |
|-------|----------:|--------------:|----------:|---------:|
| CRNN, GT quad | **91.14%** | **94.09%** | — | ~12.1 мс/номер batched |
| YOLO-pose + CRNN | 59.65% при match | 83.85% при match | **56.52%** | **200.01 мс/image** |
| YOLO26n bbox + PP-OCRv5 | — | — | 24.77% | ~146.83 мс/image |

Pose+CRNN выбран по качеству. На Kaggle CPU бюджет 100 мс не выполнен; нужен
замер на целевой GPU и, при необходимости, ONNX/TensorRT-оптимизация с повторной
проверкой exact accuracy. Для реальных type1a/type1b в validation нет читаемых
объектов, а состав upstream train для опубликованных весов неизвестен.

Ниже сохранён исторический Stage 5 benchmark legacy OCR:

Локально: AMD Ryzen 7 5700U, onnxruntime CPU, без CUDA / без ultralytics.

Увеличенный бенчмарк GT-кропов (`benchmark_latency.py --n 500`, смесь type1 /
type1a / type1b / other, только номера без `#` в GT):

| backend | n | acc@char | acc@full (95% Wilson CI) | mean ms | median ms |
|---------|--:|---------:|--------------------------:|--------:|----------:|
| **ppocrv4_mobile** | 500 | 0.739 | **0.460 [0.417, 0.504]** | 25.73 | 23.88 |
| ppocrv5_mobile | 500 | **0.795** | 0.376 [0.335, 0.419] | 26.85 | 22.97 |
| parseq | — | — | — | — | нет ONNX |

На n=60 v5 казался лучше по full-plate (38% vs 33%); при n=500 знак сменился.
Этот crop-only выбор был затем superseded полным сравнением. Для legacy
end-to-end fallback выбран v5 (24.77%). Sanity-check rec-тензоров: v4
`(1,40,97)` vs v5 `(1,40,438)`, хеши разные.

warp+OCR без детектора: ~26 мс/кроп CPU.

Полный пайплайн Этапа 6 (ONNX детектор 640 + warp + PP-OCRv4), 40 синтетических
кадров, Ryzen 7 5700U CPU: **mean 145 мс/изображение** (детектор ~104 мс, OCR
~44 мс) — **бюджет 100 мс на CPU не выполнен**. ONNX зафиксирован под imgsz 640
(другой вход отклоняется). На Tesla P100 детектор ~15 мс (Этап 4); сумма с OCR
на GPU-хосте ожидаемо внутри 100 мс, но это не замер на одном железе i5-7600 +
1050 Ti. TensorRT/INT8 — не сейчас.

CSV: `run_inference.py`; основной pose+CRNN runtime запускается по умолчанию,
legacy ONNX — с `--prefer-onnx`, GT-quad debug — с `--from-meta`.

## 6. Ограничения и расширение

Классы и геометрия шаблонов параметризованы в `src/utils/geometry.py` и
`configs/detector.yaml` — добавление новых типов/стран не требует
переписывания пайплайна.

Основной измеренный e2e exact — 56.52%; на реальных type1a/type1b качество пока
не доказано из-за отсутствия независимых читаемых примеров.

### Открытые риски (зафиксированы на Этапе 4, на Этапе 5 не переоцениваются)

Рабочий чекпоинт детектора — `weights/detector_best.pt` (34/80 эпох), заглушка
для отладки пайплайна, не финальный артефакт.

- Реальный type1: mAP50 0.934 / mAP50-95 **0.680** при смеси val 0.969 / 0.894
  (просадка локализации на реальных кадрах).
- Domain gap type1a: holdout-стиль style_b не дал просадки mAP50 (0.995 vs
  0.995), но это всё ещё процедурный генератор, не «другой реальный мир».
- Реальный type1b: **N=6**, mAP50-95 0.729 — выборка слишком мала.
