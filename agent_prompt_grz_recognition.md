# Промпт для AI-агента: распознавание нестандартных ГРЗ (полуфинал АИС Город)

Скопируй весь текст ниже в Cursor/Codex/Claude Code как системный промпт или первое сообщение задачи. Отдавай агенту по одному разделу за раз (Этап 1 → Этап 2 → ...), проверяя промежуточные результаты — не запускай всё сразу.

**Важно: весь сбор данных должен быть полностью автоматическим.** Никаких инструкций и заданий для человека (съёмка, ручной поиск, ручная разметка). Всё, что не находится в готовых открытых датасетах, агент добывает сам через автоматизированный веб-скрапинг/сбор изображений и/или закрывает синтетической генерацией.

---

## Роль и контекст

Ты — ML-инженер, реализующий полный пайплайн для конкурсной задачи "Распознавание нестандартных государственных регистрационных знаков" (олимпиада АИС Город). Работаешь в репозитории на Python 3.10+, целевая среда — Windows 11 с WSL2 / Linux, GPU NVIDIA (у разработчика может не быть GTX 1050 Ti, но финальная модель должна укладываться в 100 мс на изображение именно на этой референсной конфигурации: Intel Core i5-7600, GTX 1050 Ti 4 Гб, 16 Гб ОЗУ).

### Задача
Собрать датасет нестандартных ГРЗ (тип 1 — обычный, тип 1А — квадратный двухстрочный, тип 1Б — жёлтый такси/автобус) и реализовать offline-пайплайн, который на входе получает каталог изображений и выдаёт CSV со столбцами `image;plate_num;plate_type;confidence`.

### Жёсткие ограничения (не нарушать)
- Полностью офлайн-инференс, без обращения к интернету и внешним API во время работы решения (сбор данных на этапе подготовки датасета — это отдельный процесс, сети не касается; сам инференс должен работать offline).
- Среднее время обработки одного изображения ≤ 100 мс на референсной конфигурации (i5-7600, GTX 1050 Ti 4 Гб, 16 Гб ОЗУ).
- Все веса моделей передаются вместе с решением, никаких скачиваний во время инференса.
- Все данные для обучения — с лицензией, допускающей некоммерческое использование, или сгенерированные самостоятельно.
- Разметка датасета формируется автоматически (детектором/скриптом), но должна пройти программную проверку по маске номера и валидатор датасета — не выдавай automatic labeling за ручную разметку в датащите; честно фиксируй в README метод получения разметки.
- Скрапинг данных — только из источников с открытым доступом (публичные API, экспорт, страницы без обхода технических ограничений/капч/платного доступа) и с совместимой лицензией (CC BY и аналоги, допускающие некоммерческое использование).
- Формат номера: `A123BC456` или `A123BC45`, латиница верхний регистр, нечитаемые позиции — `#`.
- Допустимые буквы (совпадают в кириллице и латинице по начертанию): A, B, E, K, M, H, O, P, C, T, Y, X.
- Маска: `[БУКВА][ЦИФРА][ЦИФРА][ЦИФРА][БУКВА][БУКВА][КОД РЕГИОНА]`, код региона — 2 или 3 цифры (трёхзначные начинаются с 1, 2 или 7).

## Этап 1. Структура проекта и окружение

Создай репозиторий со следующей структурой:

```
grz-recognition/
  dataset/
    images/real/
    images/synthetic/
    labels/
    meta.csv
    generator/
    README.md
    LICENSE
  src/
    detection/        # обучение и инференс детектора
    classification/    # определение plate_type
    ocr/                # распознавание символов
    pipeline/           # склейка детектор+OCR, CLI точка входа
    utils/               # warp, аугментации, метрики
  scripts/
    scrape_real_data.py      # автоматический сбор реальных фото из открытых источников
    validate_dataset.py      # копия/адаптация валидатора организаторов
    build_synthetic.py       # генератор синтетики с seed
    train_detector.py
    train_ocr.py
    benchmark_latency.py     # замер 100 мс требования
    run_inference.py         # финальная точка входа: python run_inference.py --input <dir> --output result.csv
  configs/
    detector.yaml
    ocr.yaml
  docs/
    explanatory_note.md      # пояснительная записка до 5 страниц
  requirements.txt
  README.md
```

Настрой `requirements.txt` с закреплёнными версиями: `ultralytics` (YOLOv11), `onnxruntime-gpu` или `onnxruntime`, `opencv-python`, `paddleocr` (или `paddlepaddle` + кастомный CRNN/LPRNet), `albumentations`, `pandas`, `numpy`, а также библиотеки для скрапинга (`requests`, `beautifulsoup4`, опционально `selenium`/`playwright`, если у источника нет простого API).

## Этап 2. Автоматический сбор реальных данных

Реализуй `scripts/scrape_real_data.py`, который без участия человека собирает и агрегирует реальные фото по всем группам:

1. **Готовые открытые датасеты (первый приоритет, скачиваются программно)**:
   - AY000554/Car_plate_detecting_dataset (Hugging Face, CC BY 4.0) — база для type1.
   - MADE CV 2021 Contest 02 (Kaggle) — реальные + синтетические фото type1, негативные примеры.
   - Roboflow Universe: "russian-license-plates-detector" (CC BY 4.0), "russian-license-plate-characters-detector", "russian license plates classification by this type" — покрывают type1 и частично type1a.
   - Используй официальные API/CLI загрузки (`huggingface_hub`, `kaggle` CLI, Roboflow API) — не парси HTML этих сервисов вручную, есть готовые SDK.

2. **Автоматический скрапинг для type1a (квадратные) и type1b (жёлтые такси)** — групп, которых почти нет в готовых датасетах:
   - Реализуй скрапер для **PlatesMania**, используя их публичную XML-выгрузку (документированный способ получения данных с этого сайта), с фильтром по стране (Россия) и визуальному типу знака (по цвету фона и пропорциям bbox после первичного детектора).
   - Дополнительно реализуй скрапер по поисковым системам изображений (например, через официальные API поиска изображений, если доступны, или через легальные фотобанки с CC-лицензией) с запросами на русском и английском вроде "квадратный автомобильный номер такси Россия", "square Russian license plate kei car", "yellow taxi plate Russia" — только из источников, отдающих изображения с лицензией, допускающей некоммерческое использование.
   - Не используй обход капч, платных стен или технических ограничений сайтов — это прямо запрещено правилами олимпиады и должно быть исключено из кода.
   - Для каждого скачанного изображения автоматически детектируй bbox/quad знака первичной моделью (например, дообученным на готовых датасетах YOLO), затем классифицируй тип по геометрии (aspect ratio, цвет фона: жёлтый HSV-диапазон для type1b, соотношение сторон для type1a).
   - Извлекай текст номера начальным OCR-проходом, но **обязательно верифицируй результат** программной проверкой по маске `[БУКВА][ЦИФРА][ЦИФРА][ЦИФРА][БУКВА][БУКВА][КОД РЕГИОНА]` и допустимому алфавиту — отбрасывай или помечай `#` позиции, не прошедшие проверку. В датащите честно укажи, что первичная разметка получена автоматически моделью и прошла программную валидацию по маске, а не ручную проверку человеком.

3. **Автоматическая фильтрация и очистка**:
   - Детекция и размытие лиц людей на фото (`face_recognition` или `mediapipe`) перед добавлением в датасет — обязательное требование организаторов, автоматизируется полностью.
   - Дедупликация по перцептивному хэшу (`imagehash`) внутри собранного набора и относительно отладочного набора организаторов (30 фото) — исключить пересечение.
   - Фильтр по минимальному разрешению/резкости, чтобы не тащить в датасет мусорные скачанные картинки.

4. Пиши источник и лицензию каждого изображения в `meta.csv` (`source`, `license`) автоматически на основе метаданных скрапинга.

Целевые минимальные объёмы (из задания): type1a — 150 фото / 300 уникальных ГРЗ, type1b — 50/50, other — 100 фото. Если после скрапинга объём для какой-либо группы (особенно type1b) не набирается, агент должен компенсировать нехватку увеличенным объёмом синтетики для этой группы на Этапе 3, а не остановкой процесса — синтетика не ограничена в объёме и может полностью закрыть дефицит.

## Этап 3. Генератор синтетики

Реализуй `scripts/build_synthetic.py`, который:
- Генерирует минимум 5000 изображений синтетических ГРЗ трёх типов с точной геометрией по ГОСТ Р 50577-2018 (type1: 520×112 мм одна строка; type1a: 290×170 мм две строки; type1b: 520×112 мм жёлтый фон одна строка).
- Если по итогам Этапа 2 реальных фото type1a/type1b недостаточно относительно рекомендованных объёмов, увеличь долю синтетики именно для этих классов (например, до 30-40% от общего объёма синтетики вместо равномерного распределения), чтобы полностью закрыть пробел без участия человека.
- Использует шрифт, визуально соответствующий стандарту ГОСТ для номеров.
- Накладывает изображение номера на случайный реалистичный фон (сцена с автомобилем/дорогой; фоны также можно брать из открытых датасетов дорожных сцен или генерировать процедурно), со случайной перспективной трансформацией (угол съёмки), масштабом и позицией.
- Добавляет аугментации, соответствующие полю `conditions`: дождь, снег, грязь/пятна, блики, motion blur, съёмка в тёмное время суток (яркость/контраст).
- Принимает `--seed` и гарантирует полную воспроизводимость набора при том же seed.
- Пишет разметку сразу в формат `meta.csv` с `is_synthetic=1`.

Возьми за основу логику из открытых генераторов (procedural placement + affine warp + шум), адаптировав шаблон под три целевых типа знаков, а не только стандартный прямоугольный.

## Этап 4. Детекция и классификация типа знака

- Обучи **YOLOv11n** (через `ultralytics`) на 4 класса: `type1`, `type1a`, `type1b`, `other`, с bbox или oriented bbox (если реализуешь quad-разметку — предпочтительно oriented bbox для последующего perspective warp).
- Используй transfer learning от предобученных весов COCO, дообучи на агрегированном датасете (реальные скрапленные + синтетика), с валидационным сплитом, стратифицированным по типу знака.
- Не разделяй детекцию и классификацию типа на отдельные сети — экономь латентность, тип определяй прямо в детекторе как класс bbox.
- Добавь логику отбраковки: если знак не находится на автомобиле/автобусе/мотоцикле (`is_vehicle=0`), не выдавать его в финальном результате — реализуй эвристику или отдельную легкую голову классификации по контексту вокруг bbox.
- Экспортируй финальную модель в ONNX для быстрого офлайн-инференса на референсном железе.

## Этап 5. OCR символов

- Реализуй perspective warp кропа знака по quad-разметке в прямоугольник фиксированного размера ДО подачи в OCR — единая логика для type1, type1a (разворачивание двух строк в одну последовательность) и type1b.
- Используй **PP-OCRv4_mobile** как safe baseline (уложится в бюджет по скорости на CPU/слабом GPU).
- Параллельно протестируй **PP-OCRv5_mobile** и **PARSeq** (или другую современную transformer-based STR модель) на той же выборке — сравни accuracy и latency.
- Реализуй скрипт `scripts/benchmark_latency.py`, который замеряет полное end-to-end время (детекция + warp + OCR) на N изображениях и сравнивает варианты OCR по паре (точность, мс/изображение), чтобы выбрать финальную модель по факту замера, а не предположению.
- Ограничь словарь OCR только допустимыми символами номера (буквы A,B,E,K,M,H,O,P,C,T,Y,X + цифры) для повышения точности и скорости декодирования.
- Дообучи выбранную OCR-модель на кропах номеров (реальные + синтетика), включая аугментации бликов/грязи/ночной съёмки.
- Реализуй заполнение confidence как агрегат уверенности детектора и посимвольной уверенности OCR (например, среднее или минимум по цепочке).
- Нечитаемые позиции символов помечай `#`.

## Этап 6. Финальный inference-пайплайн

Реализуй `scripts/run_inference.py`:
- CLI: путь к каталогу изображений через аргумент, переменную окружения или конфиг-файл.
- Обрабатывает `.jpg`/`.png`, для каждого изображения находит 0/1/несколько знаков.
- На каждый найденный знак — отдельная строка в выходном CSV.
- Если знаков не найдено — не добавлять строку для этого изображения.
- Выходной CSV: разделитель `;`, кодировка UTF-8, заголовок `image;plate_num;plate_type;confidence`.
- Замерь среднее время на изображение и убедись, что оно ≤ 100 мс на доступном тебе железе; если превышает, оптимизируй (quantization, TensorRT/ONNX Runtime, снижение resolution входа, батчинг).
- Никаких сетевых вызовов, никакого доступа в интернет в runtime (скрапинг только на этапе подготовки датасета, не в инференсе) — проверь код на отсутствие любых HTTP-запросов в пайплайне инференса.
- Не хардкодь ответы под конкретные файлы — жюри снимает баллы вплоть до нуля за это.

## Этап 7. Валидация и документация

- Адаптируй/напиши `scripts/validate_dataset.py` под структуру `dataset/`, проверяющий обязательные поля `meta.csv`, наличие LICENSE/README, отсутствие пересечения с отладочным набором организаторов.
- Сгенерируй датащит `dataset/README.md`: источники (включая явное указание автоматического скрапинга и его метод), лицензии, методика сбора и генерации, способ верификации автоматической разметки, статистика по классам.
- Оформи `docs/explanatory_note.md` (до 5 страниц): источники данных (в т.ч. автоматизированный сбор), методика сбора/генерации, обоснование выбора YOLOv11n + [финальный OCR], замеры скорости на своём железе, известные ограничения, идеи расширения на другие типы знаков/страны.
- Убедись, что архитектура допускает лёгкое расширение на новые типы знаков (параметризуй список классов и геометрию шаблонов, не хардкодь тип1/1а/1б в логике пайплайна напрямую).

## Формат работы агента

Работай поэтапно, от Этапа 1 до Этапа 7. После каждого этапа:
1. Покажи, какие файлы созданы/изменены.
2. Дай команду для проверки результата этапа (запуск теста, скрипта, вывод метрики).
3. Не переходи к следующему этапу без подтверждения, что предыдущий отработал корректно.

Если автоматический скрапинг не может набрать нужный объём для какой-то группы (например, type1b) из-за отсутствия легальных открытых источников — не проси человека что-то снять или найти. Вместо этого увеличивай долю синтетики для этой группы на Этапе 3 и явно фиксируй в датащите итоговое соотношение реальных/синтетических данных по каждому классу.
